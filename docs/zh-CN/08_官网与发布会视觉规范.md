# 官网与发布会视觉规范

> **版本**：v0.2  
> **状态**：Architecture Preview；规范优先，非稳定组件 API  
> **更新日期**：2026-07-29  
> **适用范围**：AI Agent 工作台、企业系统、金融与数据平台、运维与可观测平台、官网、概念产品与发布会  


## 1. 目标

官网、概念产品和发布会的任务是解释产品价值、建立记忆点、证明可信度并推动下一步行动，而不是复刻生产系统的全部功能。

## 2. 信息架构

```text
Hero
Value Proposition
Product Demo
Use Cases
How It Works / Architecture
Security & Privacy
Community / Customer Proof
Pricing or Deployment Options
Documentation / GitHub / Download
CTA
FAQ
Footer
```

## 3. Neo-Glass 使用

Marketing Profile 可使用 High / Immersive：

- 大面积空间层级；
- 3D Agent 网络；
- 文件、节点和工具流动；
- 绿色光轨；
- 滚动叙事；
- 产品界面模拟；
- 视频与发布会大屏。

但每个视觉元素必须服务一个叙事节点，避免背景粒子与无意义浮动。

## 4. Hero 规范

首屏必须在不依赖 3D 加载的情况下传达：

- 产品是什么；
- 为谁解决什么问题；
- 核心差异；
- 主要 CTA；
- 信任线索。

3D、视频或 WebGL 只能增强，不得成为理解文案和操作 CTA 的前置条件。

## 5. 产品 Demo

Demo 区分：

```text
真实可交互 Demo
录制视频
动效模拟
概念动画
```

不能把概念动画伪装为已上线能力。展示 Agent 执行时，应显示目标、步骤、工具和结果，而不是只展示自动滚动聊天。

## 6. 发布会大屏

- 16:9 与超宽屏分别设计；
- 远距离可读；
- 大字号、少字段；
- 动画支持主持人节奏；
- 提供离线媒体与静态备份；
- 演示环境与真实生产数据隔离；
- 不展示 Secret、个人数据和真实客户信息。

## 7. SEO 与结构化数据

软件产品官网应根据页面实际内容考虑 `SoftwareApplication` / `WebApplication` 结构化数据，并遵守 Google 的结构化数据政策。结构化数据不保证展示富结果，页面可见内容必须与标记一致。

## 8. 性能

- 目标：至少 75% 的真实访问 LCP ≤ 2.5 秒；
- Hero 主资源优先加载；
- 3D 延迟加载；
- 移动端默认降低资源；
- 无 WebGL 提供静态图；
- 视频提供 Poster；
- 字体控制字重和子集；
- 动画资源按用户偏好条件加载。

## 9. 动效与无障碍

响应 `prefers-reduced-motion`：

- 关闭镜头运动、视差、漂浮和自动轮播；
- 保留必要的状态变化；
- 为视频和长动画提供暂停；
- 保持 CTA 与正文稳定可操作。

## 10. 验收

- 关闭 JS / WebGL 后仍能理解产品和使用 CTA；
- 移动端不强制下载桌面 3D 资源；
- Demo 明确标识真实或概念；
- 主要页面具有唯一标题、描述和社交分享信息；
- 无障碍和性能模式不破坏品牌核心；
- 发布会有离线、静态和低性能备份。
