# 运维与可观测平台设计规范

> **版本**：v0.2  
> **状态**：Architecture Preview；规范优先，非稳定组件 API  
> **更新日期**：2026-07-29  
> **适用范围**：AI Agent 工作台、企业系统、金融与数据平台、运维与可观测平台、官网、概念产品与发布会  


## 1. 目标

支持从异常发现到诊断、处置、验证和复盘的完整事件生命周期。

```text
Detect
→ Triage
→ Assign
→ Investigate
→ Mitigate
→ Verify
→ Resolve
→ Review
```

## 3. Dashboard 原则

每个 Dashboard 必须回答明确问题，按“总体 → 服务 → 实例 → 证据”下钻，降低认知负荷。避免为了填满屏幕展示无行动价值的正常指标。

## 4. 告警卡片

展示：

```text
名称
Severity
状态
受影响服务
开始时间
持续时间
负责人
关键证据
最近变更
Runbook
确认 / 静默 / 升级状态
```

正常状态尽量安静；Critical 只用于需要立即行动的事件。

## 5. Incident Workspace

推荐布局：

```text
事件摘要与影响
事件时间线
指标 / 日志 / 链路证据
参与者与沟通
Runbook 与处置动作
恢复验证
复盘与行动项
```

处置动作必须记录执行者、环境、命令或工具、结果和时间。

## 6. Metrics / Logs / Traces

### Metrics

- 明确单位和聚合方式；
- 显示阈值与基线；
- 支持时间对比；
- 重要部署或变更作为标记。

### Logs

- 高性能虚拟列表；
- 字段解析和原始日志切换；
- 时间、时区、来源和 Trace ID；
- 敏感信息脱敏；
- 查询可保存与分享。

### Traces

- 服务、Span、耗时、错误和依赖；
- 支持从告警、日志和指标跳转；
- 瀑布图必须提供结构化列表替代。

## 7. Topology

拓扑用于理解依赖和影响范围，不用于装饰。节点数量较大时提供过滤、聚合、搜索、列表和静态降级。

## 8. 告警噪声控制

UI 支持：

- Group；
- Deduplicate；
- Silence；
- Suppress；
- Escalate；
- Maintenance Window；
- Flapping 标识；
- 最近阈值变更；
- 事件后评估。

## 9. 视觉策略

- 默认 Compact；
- Dark 常用但不得强制；
- 玻璃 Low；
- 正常状态弱化；
- 异常按严重度、影响和持续时间综合表达；
- 实时更新必须可暂停；
- 夜间值班模式减少眩光与无关动效。

## 10. 验收

- 用户能在数秒内识别最重要异常；
- 告警可下钻到证据；
- 时间范围在所有视图中一致；
- 每个处置动作可审计；
- 静默和关闭有明确时限与责任人；
- 复盘保留根因、处置、恢复和后续行动。
